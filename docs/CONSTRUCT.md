# Construct

## Public definition

VideoBench measures whether a declared agentic editing stack can transform frozen source and project state into accepted, editable deliverables under a bounded work contract.

It also measures how controlled changes to the stack or work trajectory affect that result.

The public definition has four consequences:

1. The evaluated object is a configured **RunStack**, not a model family.
2. The scientific unit is a task-family form attempted from a clean starting state.
3. Success is accepted work, not merely a render or a successful tool call.
4. Causal claims require a predeclared treatment and matched controls.

## The evaluated object

```text
RunStack =
  ModelIdentity
  + HarnessPolicy
  + SurfaceProfile
  + ContextAndMemoryPolicy
  + ToolAndScaffoldPolicy
  + ResourceEnvelope
  + ResolveEnvironment
  + OperatorPolicy
```

A result may be described at the model level only when the study actually holds the other factors fixed or presents the result as a stack observation rather than a model-causal claim.

### Observation and action are independent

An agent may inspect project state through scripting, view screenshots, receive rendered proxies, use transcript analysis, act through compound MCP calls, write direct scripts, or operate the GUI. `SurfaceProfile` records observation, action, media analysis, and verification access separately.

### Operator policy is part of the result

VideoBench distinguishes:

- `autonomous`;
- `scripted_collaboration`;
- `expert_operated`.

An expert-operated result measures editor + model + product + prompting practice. It is valid field evidence. It is not an autonomous-agent result.

## Accepted work

Acceptance is gated:

```text
candidate run completed
AND artifact valid
AND hard contract passed
AND required provenance/editability established
AND semantic acceptance established
= accepted work
```

A beautiful result cannot offset a missing required quote, wrong aspect ratio, offline source media, or non-editable project when those are fatal obligations.

VideoBench therefore reports at least:

- candidate completion rate;
- artifact-valid rate;
- hard-contract pass rate;
- semantic acceptance rate;
- accepted-work rate;
- quality conditional on valid completion.

## Constructs remain separate

VideoBench does not assume that one latent capability explains all editing performance.

| Construct | What it establishes |
|---|---|
| Surface conformance | The substrate can produce and persist required state. |
| Agentic execution | The configured agent can use that substrate. |
| Editorial decision quality | The agent can choose and shape material defensibly. |
| Project completion | The full result satisfies the work contract. |
| Revision and recovery | Requested change and protected-state preservation both succeed. |
| Reliability | The result survives repeated clean attempts. |
| Economics | Accepted work is obtained under a measurable resource burden. |
| Judge validity | The measurement system can recognize the relevant distinctions. |

A shared protocol does not authorize a shared composite score.

## Work graph, not click script

A task declares obligations and dependencies, for example:

```text
understand source
    -> select material
    -> construct sequence
       + integrate graphics
       + establish audio treatment
       + satisfy format constraints
    -> quality control
    -> deliverables
```

It does not prescribe one GUI gesture sequence or one MCP method. The implementation may use structured tools, scripts, GUI control, or a hybrid while remaining comparable on the terminal work contract.

## Study-level causal claims

Each confirmatory `StudySpec` names one principal treatment and the permitted claim.

Examples:

### Tool-abstraction effect

Hold model, harness, environment, task, and budget fixed. Vary compound versus granular MCP.

### Surface effect

Hold model, task, environment, and resource envelope fixed. Vary MCP versus direct Resolve scripting.

### Revision penalty

Start from the same frozen project and require the same final obligations. Vary whether the final requirement arrives cleanly or through a revision trajectory.

A field comparison may intentionally vary several real-world factors. It should then report a stack delta and failure profile, not attribute the result to one hidden mechanism.

## Claim boundary

The first public release is an instrument-validation release. It may establish that:

- pack compilation preserves information boundaries;
- known-good work outranks known-bad work;
- independent verification catches controlled failures;
- qualified judges discriminate declared mutants;
- run and judge variance can be separated;
- evidence can be reverified, rejudged, repriced, and reprojected.

It does not yet establish population-level claims about professional editors, all Resolve tasks, or the best general-purpose model.
