# Roadmap

The roadmap follows evidence-producing vertical slices. It does not block the first useful instrument on a hosted registry, polished leaderboard, or every provider adapter.

## Current: public-alpha foundation

Complete:

- Python package and CLI;
- content-addressed artifact envelopes;
- TaskSource compiler;
- ExecutionPack / VerifierPack / JudgePack information boundary;
- generic command runner;
- manual product capture;
- immutable work-result receipts bound to exact ExecutionPack digests and instruments;
- declarative independent verifier;
- judge qualification anchors and mutant discrimination;
- judgment import and evidence-transform validation;
- gated acceptance and evidence-consistent trust receipts;
- versioned pricing and scoring;
- exact-frozen-form study specifications and family-level summaries;
- read-only Resolve state snapshot;
- ffprobe receipt;
- checked-in JSON Schemas;
- synthetic known-good / known-bad vertical demo;
- path, symlink, stale-output, budget, and protocol-variable hardening;
- CI, typing, linting, and coverage configuration.

## Next: real Resolve conformance slice

- Author a semantic capability registry.
- Map compound MCP, granular MCP, and direct scripting methods to capabilities.
- Build 25–40 bounded conformance cases.
- Add save/close/reopen persistence fixtures.
- Capture false-success and unsupported-surface outcomes explicitly.
- Produce an environment-qualification receipt.
- Add an MCP trace adapter with tool-schema hashes and raw calls.

## Next: first rights-clean media pack

- Select or commission a compact interview source package.
- Preserve original video, audio, transcript, graphics, music, room tone, and usage rights.
- Produce a strong reference, distinct acceptable alternative, minimum acceptable cut, and isolated mutants.
- Add real media and project checks.
- Calibrate evidence transforms for continuous video, audio, source context, and project state.
- Obtain professional-editor review after the concrete packet exists.

## Next: first matched surface study

Start with the cleanest treatment:

```text
same model
same harness
same task forms
same Resolve environment
same resource envelope
vary compound versus granular MCP
```

Repeat clean attempts, preserve all evidence, and report stack deltas without over-attributing hidden product behavior.

## Next: revision instrument

- Freeze an accepted starting project.
- Author requested changes and protected invariants.
- Add semantic timeline diff and edit-radius measures.
- Compare clean consolidated instruction against revision trajectory.
- Measure regression, unnecessary churn, and cost to accepted revision.

## Later

- provider-specific model and VLM judge adapters;
- GUI observation/action adapters;
- richer Resolve project canonicalization;
- family-clustered bootstrap and hierarchical analysis;
- hosted artifact registry and static report site;
- public/active/canary/retired pack release tooling;
- selective migration of stable hot paths to Rust or Go;
- package and public-name decision before registry publication.

## Explicitly deferred

- one universal VideoBench score;
- a broad public model leaderboard before instrument validation;
- automatic professional-editor replacement claims;
- arbitrary community validator execution;
- every Resolve feature in the first craft pack;
- full product-surface automation;
- a custom database as the source of truth;
- publishing under the already-collided `videobench` package name.
